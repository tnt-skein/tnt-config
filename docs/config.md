# Настройки приложения

`tnt-config` — настройки приложения одним набором: слои, слитые вглубь
(умолчания, файлы, раздел конфигурации кластера), чтение по пути
с умолчанием, чтение с родом и файлы настроек — YAML, JSON и данные Lua,
в том числе собранные заранее.

```lua
local config = require('tnt.config')

local settings = config.new(defaults, config.read('config/site.yaml'), role_cfg)   -- правее — главнее

settings:get('mail.host', 'localhost')   --> 'mx.example.org'
settings:integer('mail.port')            --> 2525: из context пришла строка '2525'
settings:boolean('mail.tls', false)      --> false

config.read('config/none.yaml')          --> nil, err.kind == 'missing'
config.write('bootstrap/cache/config.lua', sections)   --> true: подмена целиком, права 0600
```

Зависит от [`tnt-collection`](https://github.com/tnt-skein/tnt-collection)
(слияние и чтение по пути), [`tnt-fs`](https://github.com/tnt-skein/tnt-fs)
(файлы), [`tnt-env`](https://github.com/tnt-skein/tnt-env) (правила
приведения строки) и [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(проверки аргументов). Настроек и состояния у пакета нет.

## Зачем пакет

Настройки приложения собираются из нескольких мест, и у каждого места
своя причина быть: умолчание пишется в коде рядом с тем, кто им
пользуется, значение для узла приходит из окружения, а то, что записано
в конфигурации кластера, сильнее собранного на узле. Сводить их руками
значит каждый раз заново решать одни и те же вопросы — и решать
по-разному:

```lua
local function merged(base, over)
    local result = {}

    for name, value in pairs(base) do
        result[name] = value
    end

    for name, value in pairs(over) do
        if type(value) == 'table' and type(result[name]) == 'table' then
            result[name] = merged(result[name], value)
        else
            result[name] = value
        end
    end

    return result
end
```

Такое слияние сливает и списки — по номерам: `{ 'a', 'b', 'c' }` под
`{ 'd' }` даёт `{ 'd', 'b', 'c' }`, три адреса вместо одного. `null` из
YAML (`timeout: ~`) у него затирает значение, хотя значит «не задано».
А чтение `settings.mail.smtp.port` падает на первом же незаданном
разделе с «attempt to index a nil value» — без слова о том, какой
настройки не хватило.

Второе — файлы. Собранные заранее настройки (скажем,
`bootstrap/cache/config.lua`) — это файл с тайнами открытым текстом,
который узел читает на старте. Записанный на месте открытием и `write`,
он выходит читаемым для всех (`0644`), обрывается посередине при сбое
записи, числа в нём теряют знаки — `tostring(2^53)` это
`9.007199254741e+15`, — а ключ `end` делает файл нечитаемым вовсе.
Прочитанный `dofile`, он исполняет всё, что в нём написано.

Пакет даёт этому одно место: слияние по правилам `tnt-collection`,
чтение по пути с отказом, который называет путь, и файлы, которые
читаются и пишутся без этих ловушек.

## Как пользоваться

### Что умеет фасад

| Вызов | Что делает |
|---|---|
| `config.new(...)` | набор из слоёв; правее — главнее, пустой слой пропускается |
| `settings:get(path, default)` | значение по пути либо умолчание; таблица — копией |
| `settings:has(path)` | задана ли настройка |
| `settings:string`, `integer`, `number`, `boolean`, `list`, `map` `(path, default)` | значение рода; без умолчания — обязательное |
| `settings:all()` | все настройки копией |
| `settings:with(...)` | новый набор: этот и слои поверх него |
| `config.read(path)` | файл настроек `.yaml`, `.yml`, `.json` либо `.lua`; отказ — пара |
| `config.write(path, settings, opts)` | файл данных Lua: каталог заводится, файл подменяется целиком, права `0600` |
| `config.encode(settings)` | текст такого файла: `return { … }` |
| `config.INVALID` | род отказа разбора: файл прочитан, а настроек в нём нет |
| `config.MODE` | права файла, который пишет `write`, — `0600` |

### Слои

```lua
local settings = config.new(
    { http = { timeout = 3, retries = 2 }, hosts = { 'a', 'b', 'c' } },   -- умолчания
    { http = { timeout = 5 }, hosts = { 'd' } },                           -- файл
    { http = { retries = box.NULL } }                                      -- раздел роли
)

settings:all()   --> { http = { timeout = 5, retries = 2 }, hosts = { 'd' } }
```

Правила слияния — `collection.merge_deep`
([`tnt-collection`](https://github.com/tnt-skein/tnt-collection/blob/main/docs/collection.md),
«Слияние настроек»): словари сливаются по ключам, списки и всё прочее
заменяются целиком, `box.NULL` значения не затирает, пустая таблица без
пометки принимает вид того, что заменяет. Порядок слоёв —
по возрастанию силы; какой слой каким идёт, решает тот, кто собирает
набор (см. «Граница с конфигурацией кластера»).

Набор — снимок. Слои копируются при сборке, и правка слоя после неё набор
не меняет; таблица, отданная чтением, — тоже копия. `with` набор
не трогает, а отдаёт новый:

```lua
local tuned = settings:with({ http = { timeout = 1 } })

tuned:get('http.timeout')      --> 1
settings:get('http.timeout')   --> 5
```

Слой — словарь настроек либо `nil`. Иное — ошибка в коде, и отказ
показывает на строку вызывающего:

```lua
config.new({ 'a', 'b' })         --> бросок: app.lua:11: слой 1 — словарь настроек, а не список
config.new({ a = 1 }, 'x')       --> бросок: app.lua:12: слой 2 — словарь настроек, а не строка
```

Список не годится в слой и пустым: разобранный `[]`, слитый поверх
словаря, заменил бы его целиком. Кольцо в слое — отказ `merge_deep`:
`merge_deep: таблица 1 содержит саму себя — слить кольцо нельзя`, где
номер — номер слоя.

### Чтение по пути

```lua
local settings = config.new({
    app = { name = 'demo', port = 8080, hosts = { 'a', 'b' }, debug = false },
    labels = { ['app.kubernetes.io/name'] = 'orders' },
    none = box.NULL,
})

settings:get('app.name')                                  --> 'demo'
settings:get('app.hosts.2')                               --> 'b'
settings:get({ 'labels', 'app.kubernetes.io/name' })      --> 'orders'
settings:get('app.timeout', 30)                           --> 30
settings:get('none', 'нет')                               --> 'нет'
settings:get('app.debug', true)                           --> false: ложь — значение
settings:has('app.debug'), settings:has('app.timeout')    --> true, false
```

Путь — звенья через точку либо список звеньев, когда в ключе есть
точка; звено из цифр — номер в списке. «Нет значения» — это `nil`,
`box.NULL` и NaN: `get` отдаёт умолчание, `has` — `false`. Правила пути
те же, что у `collection.get`, и опечатка в пути — отказ на строке
вызывающего:

```lua
settings:get('app..name')   --> бросок: app.lua:7: get: путь — непустые звенья через точку, а не «app..name»
```

Таблица отдаётся копией: список, дополненный у себя, в наборе остаётся
прежним.

### Чтение с родом

```lua
settings:string('app.name')          --> 'demo'
settings:integer('app.port')         --> 8080
settings:integer('app.workers', 4)   --> 4: не задано — умолчание
settings:list('app.hosts')           --> { 'a', 'b' }
settings:map('app.none', nil)        --> nil: умолчание nil — настройка необязательна

settings:integer('app.workers')      --> бросок: настройка app.workers не задана
settings:string('app.port')          --> бросок: настройка app.port — строка, а не число
settings:map('app.hosts')            --> бросок: настройка app.hosts — словарь, а не список
```

Без умолчания настройка обязательна, с умолчанием — нет, в том числе
с умолчанием `nil`: `settings:map('cache', nil)` значит «раздела может
не быть». Различается это числом аргументов, поэтому обёртка, которая
передаёт умолчание дальше, передаёт его всегда — и настройку делает
необязательной.

| Род | Годится как есть | Строка приводится |
|---|---|---|
| `string` | строка | — |
| `integer` | число без дробной части, 64-битное целое | `'3000'` → 3000 |
| `number` | число, 64-битное целое | `'0.25'` → 0.25 |
| `boolean` | `true`, `false` | `true`, `false`, `1`, `0`, `yes`, `no`, `on`, `off` |
| `list` | список, в том числе пустая таблица | через запятую: `'r1, r2'` → `{ 'r1', 'r2' }` |
| `map` | словарь, в том числе пустая таблица | — |

Отказ о настройке — **бросок без места**: текст уходит оператору
в alerts применения конфигурации либо в терминал сборки и называет
путь, а строка внутри пакета отправила бы искать не туда. **Значения
в тексте нет**: среди настроек лежат пароли, а отличить их по пути пакет
не берётся — оператору довольно пути, значение он найдёт сам.

Умолчание не того рода — ошибка в коде, и отказ о ней показывает
на строку вызывающего:

```lua
settings:integer('app.port', '8080')   --> бросок: app.lua:21: умолчание app.port — целое число, а не строка
```

## Граница с конфигурацией кластера

Пакет держит **настройки приложения**: пороги, паузы, переключатели,
адреса чужих служб. **Конфигурацию кластера** — `config.yaml` или etcd:
учётные записи, адреса `listen`, репликацию, роли, `roles_cfg` — читает
сам Tarantool, и пакет её не читает и в неё не пишет. Правило «одна
настройка — в одном месте» то же, что у окружения
([`tnt-env`](https://github.com/tnt-skein/tnt-env/blob/main/docs/env.md),
«Граница с `config.context`»): порт сервера, объявленный
у `roles.httpd`, не заводит ещё и настройку приложения.

Что приложению нужно из конфигурации кластера, отдаёт сам Tarantool:
раздел роли из `roles_cfg` приходит в `validate` и `apply` роли. Когда
раздел роли и настройки приложения говорят об одном, раздел роли кладут
**последним слоем**: записанное в кластере сильнее собранного на узле,
иначе узел с забытой переменной окружения тихо отвечал бы не тем, что
записано в кластере.

```lua
local settings = config.new(defaults, sections_from_env, role_cfg)
```

Так собирает свои настройки, например, роль панели: умолчания в коде,
файл настроек приложения и раздел роли — последним. `listen: ~`
в разделе роли порта, заданного файлом, не отнимает:

```lua
local panel = config.new(
    { listen = 8081, prefix = '/admin' },     -- умолчания в коде
    { listen = 9000 },                        -- файл настроек приложения
    { listen = box.NULL, prefix = '/ops' }    -- раздел роли: listen: ~
)

panel:all()   --> { listen = 9000, prefix = '/ops' }
```

Значение, подставленное в конфигурацию кластера из `{{ context.* }}`,
приходит в роль **строкой**, даже если в окружении было число:
`bucket_count: '{{ context.bucket_count }}'` — это `'3000'`. Приводить
род должен тот, кто читает, и чтение с родом делает это само — по тем же
правилам, по которым `tnt-env` приводит переменную окружения: значение
одно, и откуда бы оно ни пришло, читаться обязано одинаково.

```lua
local role = config.new({ role = { bucket_count = '3000', debug = 'true', hosts = 'r1, r2', weight = 'много' } })

role:integer('role.bucket_count')   --> 3000
role:boolean('role.debug')          --> true
role:list('role.hosts')             --> { 'r1', 'r2' }
role:number('role.weight')          --> бросок: настройка role.weight — число, а строка им не читается
```

## Файлы настроек

```lua
local app = config.read('config/app.json')   -- {"name": "demo", "limit": 18446744073709551615, "proxy": null}
--> { name = 'demo', limit = 18446744073709551615ULL, proxy = box.NULL }

config.read('config/empty.yaml')
--> nil, файл настроек config/empty.yaml не разобран: в нём не словарь настроек, а nil
config.read('config/list.json')
--> nil, файл настроек config/list.json не разобран: в нём не словарь настроек, а список
config.read('config/code.lua')   -- return { passwd = io.open('/etc/passwd'):read('*a') }
--> nil, файл настроек config/code.lua не разобран: config/code.lua:1: attempt to index global 'io' (a nil value)

config.read('config/app.toml')
--> бросок: файл настроек config/app.toml: расширение — .yaml, .yml, .json либо .lua
```

Формат — по расширению: `.yaml` и `.yml`, `.json`, `.lua`. Угадывать
формат по содержимому пакет не берётся — угаданный однажды угадался бы
неверно, — и незнакомое расширение ошибка в коде: путь пишет
программист, а не оператор.

Файл обязан нести **словарь настроек и только данные**: строки, числа,
логические, таблицы из них, `null` и 64-битные целые, которыми YAML
и JSON отдают число за пределом 2^53. Пустой файл, `null`, список,
функция внутри, ключ не строкой и не числом — отказ `invalid`, а не
пустые настройки: оборванный на записи файл, прочитанный как «настроек
нет», поднял бы приложение без единой из них, и молча.

**Файл Lua — данные, а не код.** Он грузится без байт-кода и с пустым
окружением: ни `require`, ни `os`, ни иные глобалы ему не видны,
а скомпилированный кусок не грузится вовсе. Литералы при этом работают
все — `1/0`, `5ULL`, строки с экранированием, — и именно ими пишет
файл `config.write`.

### Отказ

Отказ — пара `nil, err`, и род у `err` решает, что случилось:

| Род | Когда |
|---|---|
| `missing`, `denied`, `full`, `failed`… | отказ диска — от `tnt-fs` как есть ([`tnt-fs`](https://github.com/tnt-skein/tnt-fs/blob/main/docs/fs.md), «Отказ») |
| `invalid` (`config.INVALID`) | файл прочитан, а настроек в нём нет |

Вид у обоих один: поля `kind`, `message`, `path`, а строкой, в склейке
и в JSON отказ — свой текст:

```lua
local _, err = config.read('config/empty.yaml')

err.kind            --> 'invalid'
err.path            --> 'config/empty.yaml'
'причина: ' .. err  --> причина: файл настроек config/empty.yaml не разобран: в нём не словарь настроек, а nil
```

## Собранное заранее: `write` и `encode`

```lua
config.write('bootstrap/cache/config.lua', { app = { name = 'demo' } }, { comment = 'Собрано заранее.' })
--> true
```

```lua
-- Собрано заранее.
return {
    app = {
        name = "demo",
    },
}
```

Файл пишется так, чтобы читался обратно тем же и ничем иным:

```lua
config.encode({ app = { name = 'demo', hosts = { 'a', 'b' }, ['end'] = 1, limit = 2^53, ratio = 0.1 + 0.2, far = math.huge } })
```

```lua
return {
    app = {
        ["end"] = 1,
        far = 1/0,
        hosts = {
            [1] = "a",
            [2] = "b",
        },
        limit = 9007199254740992,
        name = "demo",
        ratio = 0.30000000000000004,
    },
}
```

- **Число — кратчайшей записью, которая читается тем же числом.** `%.14g`
  теряет знаки у `2^53` и у `0.1 + 0.2`, и тогда пишется `%.17g`.
  Бесконечность и NaN — `1/0`, `-1/0` и `0/0`: `inf` и `nan` в Lua — имена
  глобалов, и в пустом окружении они пусты. 64-битное целое — литералом
  `LL`/`ULL`.
- **Слово Lua ключом — в скобках**: `{ end = 1 }` не прочитал бы никто.
  Прочие ключи не-имена и числа — тоже в скобках.
- **Ключи по порядку** — числа по возрастанию, затем строки: файл
  не меняется от сборки к сборке, и разница двух сборок видна глазом.
- **`box.NULL` под ключом-строкой не пишется** — он и значит «не задано»;
  на месте в списке он оставил бы дыру, и список прочитался бы словарём —
  это отказ.

Настройки не данными — ошибка в коде, и отказ называет место внутри
настроек, а бросок показывает на строку вызывающего:

```lua
config.encode({ app = { handler = print } })
--> бросок: настройки.app.handler — функция, а в файл настроек ложатся только данные
config.encode({ hosts = { 'a', box.NULL } })
--> бросок: настройки.hosts.2 — box.NULL на месте в списке: дыра прочиталась бы словарём
```

`write` заводит каталог файла и подменяет файл целиком (`fs.replace`):
читающий видит старое либо новое, но не половину, а сорвавшаяся запись
оставляет прежний файл целым. **Права — `0600`** и поверх файла
с правами шире: в собранных настройках тайны лежат открытым текстом.
Отказ диска — пара от `tnt-fs`:

```lua
config.write('blocker/config.lua', {})   -- blocker — файл, а не каталог
--> nil, каталог blocker не создан: File exists
```

Так собранное заранее и живёт: сборка приложения пишет файл `write`,
а узел на старте читает его `read` — тем же пакетом и по тем же правилам,
что и файл, написанный руками.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.
Файлы пишутся и читаются на настоящем диске, в своём временном каталоге
на каждую проверку; двойник — только `fio` у `tnt-fs` там, где исправный
диск отказа не даст (подмена сорвалась на переименовании).

- `settings_test.lua` — слои и их порядок, снимок, чтение по пути,
  рода и приведение строки, отказы с путём и без значения, место броска.
- `reader_test.lua` — форматы, отказы диска и разбора, данные против
  кода, пустой файл, вид отказа.
- `writer_test.lua` — вид файла, числа и строки туда и обратно, слова
  Lua ключами, порядок ключей, не данные, права, шапка, подмена.

Место броска сверяется файлом, а не номером строки: следующий по стеку
кадр лежит уже в другом файле, так что уровень вины, съехавший на кадр
в любую сторону, проверка видит.

```sh
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование, порог 100 % убитых
```

Проверок — 45; покрытие строк — 100 %, убитых мутантов — 100 %
(285 мутантов в пяти модулях; в фасаде `tnt/config.lua` мутировать
нечего — ни развилок, ни чисел).

## Чем пришлось поступиться

**Отказ о настройке бросается, а не возвращается парой.** Чтение с родом
работает на сборке приложения, а негодная настройка — повод не собраться:
бросок из роли Tarantool покажет в alerts применения конфигурации.
Пара на каждом чтении значила бы проверку на каждой строке сборщика —
и однажды забытую. Пару отдаёт один `read`: файл — внешний мир, и его
отсутствие «так бывает».

**Значения в тексте отказа нет** — и там, где оно не тайна. Порт
«восемь» оператор увидит, открыв файл; пароль, вышедший в alerts,
не спрячешь.

**`with` и `new` копируют слои целиком**, и `get` таблицы — тоже.
Настройки читаются на сборке, а не на каждый запрос, и цена копии там
ничто; снимок же не даёт правке у одного пользователя дойти до другого.

**Пометка вида пустой таблицы в файл не ложится.** Разобранный `{}`
помечен словарём и уехал бы в JSON как `{}`, а прочитанный из собранного
файла — нет: в пустом окружении пометку ставить нечем. Пустой словарь,
который обязан уехать в JSON словарём, помечают там, где его отдают
(`collection.as_map`).

**Файл Lua — не песочница.** Пустое окружение закрывает глобалы, но цикл
без конца или строку в гигабайт файл устроит так же, как обычный код.
Защищает это от чужой строки в файле собранного, но не от того, кто
вправе писать в каталог приложения.

**Кольцо в слое называет себя словами `merge_deep`.** Отказ приходит
от `tnt-collection` как есть — с номером слоя, но с именем его действия.
